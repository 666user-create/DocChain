# DocChain — 本地静默文档版本管理器

为文档工作者打造的零感知版本控制工具。在你专心写文档的同时，DocChain 静默守护每一次保存，让你随时回到任何一个历史版本。

## 为什么需要 DocChain？

办公室工作者日常面对大量 Word/Excel/PPT 文档，反复修改是常态。当你删掉一段文字、改了一个数据，几小时后才后悔——你需要的不是"撤销"，而是"回到那个版本"。Git 是为代码设计的，对办公用户并不友好。DocChain 填补了这个空白：

- **零感知自动存档** — 保存即提交，无需手动操作
- **原位追踪** — 文档留在原来的文件夹里，不需要复制搬家
- **无侵入** — 静默运行在系统托盘，不弹窗、不打扰

## 核心功能一览

### 多目录原位追踪
支持添加任意多个文件夹进入监听列表。文档留在原地（`D:\文档\2025年\...`），DocChain 在后台追踪所有变更。每个监听目录下自动创建 `.docchain-git` 仓库（不可见），与用户已有的 `.git` 互不干扰。

### 智能文件监听
- 基于 JDK `WatchService`，零外部依赖
- **防抖机制**（2 秒窗口）：模拟 Office 保存行为，同一文件频繁写入只触发一次 commit
- **智能过滤**：自动忽略 `~$` Office 锁定文件、`.tmp`/`.swp` 临时文件、`.DS_Store` 系统文件
- **无变更不提交**：逐字节比对文件内容，内容未变则跳过，不产生空 commit

### 版本时间线
- 点击文件 → 右侧显示完整版本历史，按时间倒序排列
- 每个版本卡片展示：时间戳、commit hash、变更摘要
- **Diff 对比**：选中两个版本，文本文件展示行级差异（`+新增 / -删除 / ~修改`），二进制文件对比大小变化
- **一键回滚**：任意版本一键恢复，自动产生回滚记录

### 标签系统
为版本打上自定义标签（如"定稿"、"老板看过"、"v2.0"），支持按标签筛选时间线，快速定位重要版本。

### 备注笔记
为每次提交添加文本备注，记录"为什么这样改"——比 commit message 更灵活，比事后回忆更可靠。

### 批次管理
暂停监听 → 输入批次名称 → 恢复监听，期间所有自动提交归入同一批次。适合章节重写、阶段性修改等场景。

### 搜索与日期筛选
- 按文件名模糊搜索
- 按日期范围筛选文件列表

### 右键菜单集成（Windows）
安装后，在资源管理器中右键任意文件或文件夹 → "用 DocChain 追踪"，该目录即被加入监听列表。无需打开主面板。

### 系统托盘驻留
DocChain 开机自启，静默运行在系统托盘。右键托盘图标可：
- 打开主面板查看版本历史
- 暂停/恢复监听
- 启用/禁用右键菜单
- 手动提交特定文件
- 退出程序

## 技术栈

| 层面 | 技术选型 | 说明 |
|------|---------|------|
| 语言 | **Java 21** | LTS 版本，虚拟线程、文本块等现代特性 |
| 构建 | **Gradle** + jlink + jpackage | 编译 → 定制 JRE → 原生安装程序一条龙 |
| UI | **JavaFX 21** + AWT SystemTray | 双框架共存，`Platform.runLater()` 桥接线程 |
| 版本引擎 | **JGit 6.10** | 纯 Java Git 实现，每个监听目录一个 `.docchain-git` 仓库 |
| 持久化 | **SQLite** (WAL 模式) | 标签、备注、批次、监听目录列表均存储在此 |
| 差异对比 | **java-diff-utils** | 文本文件行级 diff，二进制文件大小对比 |
| 日志 | **SLF4J + Logback** | 滚动日志（10MB × 30 天，200MB 上限） |

## 项目结构

```
src/main/java/com/docchain/
├── MainApp.java                  # 应用入口，多目录架构编排
├── core/

│   └── GitRepositoryManager.java # Git 仓库管理器（增量提交、diff、回滚）
├── db/
│   └── DbManager.java            # SQLite 持久化层（标签/备注/批次/目录）
├── model/
│   ├── VersionCommit.java        # 版本提交数据模型
│   ├── DocumentTag.java          # 文档标签模型
│   ├── RepositoryConfig.java     # 仓库配置模型
│   └── WatchDirectory.java       # 监听目录模型
├── ui/
│   ├── MainPanelController.java  # 主面板（文件列表 + 版本时间线）
│   ├── SystemTrayManager.java    # 系统托盘管理器
│   ├── DiffViewer.java           # 版本差异对比窗口
│   └── Toast.java                # 轻量级 Toast 通知
└── util/
    ├── ContextMenuManager.java   # Windows 右键菜单（HKCU 注册表）
    └── PlatformUtils.java        # 跨平台工具（AppData 路径等）
```

## 安装

### 方式一：安装程序（推荐）

下载 `DocChain-1.0.exe`，双击安装。自带 JRE，无需安装 Java。

安装后在开始菜单找到 "DocChain" 快捷方式，或设置开机自启。

### 方式二：从源码构建

```bash

git clone <repo-url> && cd DocChain

# 2. 编译 + 运行测试

# 3. 直接运行

# 4. 打包原生安装程序（需要 JDK 21+，首次运行自动下载 WiX Toolset）

# 输出: build/dist/DocChain-1.0.exe
```

## 使用指南

### 首次启动

1. 双击运行 DocChain
2. 系统托盘出现蓝色图标 — 表示正在运行
3. DocChain 自动创建默认 workspace（`%APPDATA%/DocChain/workspace`）

### 添加监听目录

**方法一：右键菜单（最方便）**
1. 在托盘右键菜单中确认"右键菜单"已启用
2. 在资源管理器中，右键任意文件夹 → "用 DocChain 追踪"
3. 右下角弹出 Toast："已添加监听: 文件夹名"
4. 打开主面板，新目录的文件列表已经出现

**方法二：主面板**
1. 双击托盘图标打开主面板
2. 点击左侧下方 "+ 添加目录" 按钮
3. 选择要追踪的文件夹 → 确定

### 查看版本历史

1. 打开主面板
2. 左侧文件列表中找到目标文件（支持搜索、日期筛选）
3. 点击文件 → 右侧显示完整版本时间线
4. 每个版本卡片显示时间、hash 缩写、变更信息

### 对比版本差异

1. 在时间线上，按住 `Ctrl` 选中两个版本
2. 点击"对比选中"按钮 → 弹出 Diff 窗口
3. 文本文件：行级差异高亮（绿色新增、红色删除、橙色修改）
4. 二进制文件（.docx/.xlsx/.pdf）：显示文件大小变化

### 回滚到历史版本

1. 在时间线上找到目标版本
2. 点击版本卡片上的"回滚"按钮
3. 文件内容立即恢复，同时产生一条新的提交记录（"回滚至版本: xxxxxxx"）

### 添加标签

1. 点击版本卡片上的"+标签"按钮
2. 选择已有标签或输入新标签名
3. 标签以彩色徽章显示在版本卡片上
4. 使用时间线上方的标签下拉框按标签筛选

### 添加备注

1. 点击版本卡片上的"备注"按钮
2. 在弹窗中输入备注内容
3. 备注内容显示在版本卡片上

### 批次管理

适合"现在要重写第三章，把期间的所有改动归为一组"这种场景：

1. 右键托盘图标 → "暂停监听"
2. 弹窗中输入批次名称（如"第三章重写"）→ 确定
3. 正常编辑文档 — 所有自动提交归入此批次
4. 完成阶段性工作 → 右键托盘 → "恢复监听" → 批次结束

在主面板的时间线上，同一批次的版本会有橙色批次标签。

### 手动提交

需要立即存档某个文件（不等待防抖）：

1. 右键托盘图标 → "手动提交..."
2. 在对话框下拉列表中选择文件
3. 输入备注（可选）→ 提交

### 搜索与筛选

- **文件名搜索**：左侧搜索框输入关键词，实时过滤
- **日期筛选**：选择起始/截止日期，只显示该时间段内修改过的文件
- **标签筛选**：右侧时间线上方按标签过滤版本
- 点击"清除筛选"恢复完整列表

## 数据存储

| 数据 | 存储位置 | 说明 |
|------|---------|------|
| 版本历史 | `<监听目录>/.docchain-git/` | 每个目录独立的 Git 仓库 |
| 标签/备注/批次 | `%APPDATA%/DocChain/docchain.db` | SQLite 数据库 |
| 监听目录列表 | `%APPDATA%/DocChain/docchain.db` | `watched_directories` 表 |
| 右键菜单队列 | `%APPDATA%/DocChain/pending-watch.txt` | 轮询消费后自动清空 |
| 应用日志 | `~/.docchain/logs/docchain.log` | 滚动日志，30 天保留 |

**卸载说明**：DocChain 不会修改你的文档文件。卸载只需删除安装目录，并手动删除 `%APPDATA%/DocChain/`。各监听目录下的 `.docchain-git/` 可以保留（未来重装可恢复）或直接删除。

## 安全设计

- **完全本地**：所有数据存储在本地，无网络通信，无遥测
- **HKCU 注册表**：右键菜单写入当前用户注册表，无需管理员权限
- **PowerShell 注入防护**：右键菜单中的路径参数对单引号做 PowerShell 转义（`''`）
- **无敏感数据**：不扫描、不上传文件内容

## 常见问题

**Q: DocChain 会影响电脑性能吗？**
A: 监听基于操作系统文件事件通知，不轮询磁盘。内存占用约 80-120MB（含 JVM）。

**Q: 每个目录下都有 `.docchain-git`，会不会很大？**
A: Git 只存储文件差异（delta），对于 Office 文档（本质是 ZIP 包），增量存储效率很高。一个包含 100 个版本的 `.docx` 文件，仓库大小通常在原始文件的 2-5 倍。

**Q: 能卸载吗？会删除我的原始文件吗？**
A: 可以卸载，DocChain 永远不会删除你的原始文件。卸载后，各目录下的 `.docchain-git/` 可以手动删除，或保留以备重装后恢复版本历史。

**Q: 支持 macOS / Linux 吗？**
A: 核心功能全平台支持。右键菜单集成仅限 Windows（依赖注册表）。macOS/Linux 上通过主面板的"+ 添加目录"按钮添加监听目录。

**Q: 能追踪代码项目吗？**
A: 可以，但不推荐。DocChain 的 `.docchain-git` 目录会与代码项目的 `.git` 独立共存，互不干扰。但对于代码，专业的 Git 客户端（如 VS Code Git、GitKraken）是更好的选择。DocChain 专为**非技术用户的文档版本管理**设计。
